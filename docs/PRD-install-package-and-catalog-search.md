# PRD — 설치형 패키지 판매와 목록형 조회

작성일: 2026-10-30  
상태: 제안 — 구현 전. 파트너 에이전시 상품 설명서에 적은 두 패키지를 실제로 팔고 운영하기 위해 필요한 것을 정리한다.  
연결: [실시간 조회](PRD-db-live-lookup.md) · [DB 지식 연동](PRD-db-knowledge-source.md) · [데이터 비서](PRD-data-assistant.md) · [상담 담당자 로그인·고객사별 권한](PRD-agent-login-and-customer-access.md)

## 1. 배경

파트너 에이전시에게 아래 두 패키지를 제안한다. 월 이용료 없이 고객사 한 곳당 설치비만 받고, 첫 도입 1년은 운영비가 없다.

| 패키지 | 설치비(고객사 1곳, 최초 1회) | 포함 내용 |
| --- | --- | --- |
| RAG AI 챗봇 설치 | 590,000원 | Q&A 챗봇 + 상담원 연결 또는 Q&A + AI 결합 + 상담원 연결 중 선택, 운영 시간 설정, 홈페이지 직접 설치, 초기 Q&A 설정, 홈페이지 주소로 지식 등록, 그 밖의 자료 초기 세팅 |
| RAG AI 챗봇 + DB 연동 (Beta) | 790,000원 | 위 내용 전부 + 고객사 서비스 DB에서 조건에 맞는 상품을 찾아 추천(예: 호텔 서비스 "제주도 갈 건데 스파 있는 호텔 찾아줘", 가구점 "20만원 이하 3인용 소파 추천해줘") + 재고 같은 지금 값 조회. 고객사별 맞춤 설정 |

지금 제품으로 590,000원 패키지의 기능은 모두 운영 중이다. 790,000원 패키지와 "설치비 + 1년 무료" 판매 방식에는 아래가 빠져 있다.

| 필요한 것 | 지금 상태 | 이 문서 |
| --- | --- | --- |
| 조건에 맞는 상품 여러 개를 골라 추천 | 실시간 조회는 결과가 최대 결과 수를 넘으면 거절한다 | §3 목록형 조회 |
| 고객사마다 패키지·운영 기간을 기록하고 만료를 관리 | 요금제·한도가 에이전시 단위로만 있다. 고객사에는 계약 정보 칸이 없다 | §4 고객사 계약 |
| 고객사마다 대화량·DB 한도를 따로 적용 | 월 대화 세션·DB 행 한도가 에이전시 합계다 | §4 고객사 계약 |
| DB 기능을 790,000원 패키지 고객사에만 열기 | DB 기능은 에이전시 요금제(그로스 이상)로만 열린다 | §4 고객사 계약 |
| DB 연동 기능을 운영에 배포 | 통합 브랜치에만 있다 | §5 운영 배포 |
| 맞춤 설정을 우리가 대신 해 주는 절차 | 화면은 있으나 우리 운영자가 고객사 DB를 설정하는 절차·권한이 정해지지 않았다 | §6 맞춤 설정 |
| 장애·오류를 나중에 찾아보기 | 서버 로그가 Vercel에 짧게만 남고, 위젯 오류는 남지 않는다 | §7 오류 기록 |

### 다루지 않는 것

- 날짜별 빈 방·실시간 가격처럼 예약 시스템 API로만 얻는 정보 — API 연동은 별도 PRD
- 고객사 직원용 집계 질문("어제 견적 몇 건?") — [데이터 비서](PRD-data-assistant.md) 1차 범위
- 결제·세금계산서 자동화 — 설치비는 계약서·계좌 이체로 받고, 시스템에는 기록만 한다

## 2. 목표와 성공 기준

- 에이전시가 미팅에서 790,000원 패키지를 실제 화면으로 보여줄 수 있다: 데모 호텔·가구 DB로 "조건에 맞는 상위 5곳 + 상세 링크"가 답으로 나온다.
- 고객사를 만들 때 패키지와 운영 시작일을 고르면, 1년 뒤 만료 30일 전에 에이전시와 마스터가 알 수 있다.
- 한 고객사에 대화가 몰려도 다른 고객사 챗봇이 멈추지 않는다.
- 590,000원 패키지 고객사에서는 DB 연동 화면이 "상위 패키지에서 쓸 수 있어요"로 잠긴다.

## 3. 목록형 조회 (상품 조건 검색·추천)

### 3.1 무엇이 다른가

| | 단건 조회(지금) | 목록형 조회(추가) |
| --- | --- | --- |
| 쓰는 곳 | 재고·잔여석 같은 지금 값 | 조건에 맞는 상품 찾기·추천 |
| 결과가 최대 수를 넘으면 | 값을 주지 않고 "범위가 너무 넓어요" | 정한 기준으로 상위 N개만 돌려주고 "조건을 더 알려주시면 좁혀 드릴게요" |
| 조건 | 필수 조건 1개 이상(같음·포함) | 선택 조건 여러 개(같음·포함·이상·이하·범위). 하나 이상은 채워져야 함 |
| 정렬 | 없음 | 고객사가 정한 기준(평점 높은 순, 가격 낮은 순 등) 중 하나 |
| 링크 | 없음 | 상세 페이지 주소 컬럼(또는 주소 틀 `https://.../hotel/{id}`) |

### 3.2 설정 화면 (기존 실시간 조회 마법사에 종류 선택 추가)

1. 조회 종류: **단건 조회** / **목록형 조회**
2. 연결·표, 이름·쓰는 때(예: "방문자가 조건에 맞는 호텔을 찾을 때")
3. 조건 컬럼 최대 5개: 컬럼, 라벨, 비교 방식(같음·포함·이상·이하·범위), 숫자 단위. 예: 지역(포함), 편의시설(포함), 1박 가격(이하), 성급(이상)
4. 답에 쓸 컬럼: 이름·지역·가격·평점·한 줄 소개
5. 정렬 기준: 컬럼 + 방향(평점 높은 순 등), 동점이면 고유키 순
6. 상세 링크: 주소가 든 컬럼을 고르거나, 주소 틀에 컬럼 값을 넣는다. 고객사 홈페이지 도메인만 허용
7. 보여줄 개수 N(1~5, 기본 5), 항상 적용할 조건(판매 중만 등)
8. 테스트: 조건 값 입력 → 상위 N개 + 전체 일치 건수 표시
9. 예시 질문(최대 3개)

### 3.3 실행

- 질의: 항상 적용할 조건 + 채워진 조건 + `ORDER BY 정렬 컬럼, 고유키 LIMIT N+1`. 값은 바인딩, 식별자는 인용(지금 커넥터 규칙 그대로).
- N+1번째 행이 있으면 "더 있음"만 표시하고 전체 개수는 세지 않는다(큰 표에서 COUNT가 무겁다).
- 채워진 조건이 하나도 없거나 값이 "전체"류면 실행하지 않는다(지금 G2·G3 규칙 재사용).
- 5초 실행 제한, 메시지당 2회, 대화당 10분 10회, 챗봇당 분당 60회, 30초 캐시는 그대로 적용한다.
- 모델에는 라벨이 붙은 결과와 상세 링크만 보낸다. 원본 컬럼 이름은 보내지 않는다.
- 위젯: 답 아래 결과 카드(이름·핵심 값 2~3개·"자세히 보기" 링크)를 최대 N개 표시한다. 링크는 새 탭으로 연다.

### 3.4 질문 해석

- 모델이 질문에서 조건 값을 채운다: "제주도" → 지역 포함 "제주", "스파" → 편의시설 포함 "스파", "20만원 이하" → 가격 이하 200000.
- 숫자 표현은 DB 지식의 숫자 해석(`parseKoreanNumber`·`parseNumericIntent`)을 재사용해 서버에서 한 번 더 검증한다.
- 동의어(스파/사우나, 3인용/3인)는 1차에서 고객사가 "값 바꾸기"처럼 동의어 목록을 적게 한다. 자동 동의어는 후속.

### 3.5 인수 테스트

| 번호 | 시나리오 | 기대 |
| --- | --- | --- |
| K1 | 호텔 표 30곳, "제주 스파 호텔" | 제주·스파 조건 일치 중 평점 상위 5곳 + 링크, "더 있음" 안내 |
| K2 | "20만원 이하 3인용 소파" | 가격 ≤ 200,000 · 인원 3 일치 중 가격 낮은 순 5개 |
| K3 | 조건 없이 "호텔 추천해줘" | 실행하지 않고 지역·조건을 되묻는다 |
| K4 | 일치 0건 | "조건에 맞는 상품이 없어요" + 조건 완화 제안, 지어내지 않음 |
| K5 | 상세 링크 주소 틀이 다른 도메인 | 저장 거부 |
| K6 | 5초 넘는 질의 | timeout, 숫자·상품 지어내지 않음 |
| K7 | 위젯 결과 카드 | 최대 N개, 링크 새 탭, 모바일 폭에서 가로 넘침 없음 |

## 4. 고객사 계약 (패키지·운영 기간·고객사별 한도)

### 4.1 데이터

`customer_contracts`(고객사당 현재 계약 1개, 이력 보관):

| 컬럼 | 설명 |
| --- | --- |
| customer_id | 고객사 |
| package | `rag`(590,000원) / `rag_db`(790,000원) |
| setup_fee | 설치비(원). 파트너 할인 반영 금액 |
| starts_at / free_until | 운영 시작일 / 운영비 무료 종료일(기본 시작일 + 1년) |
| monthly_session_limit | 고객사별 월 대화 세션 한도(기본값은 패키지별) |
| db_row_limit | DB 지식 행 한도(`rag_db`만) |
| status | `active` / `expired` / `cancelled` |
| memo, created_by, created_at | 계약 메모와 감사 |

### 4.2 규칙

- DB 연동·실시간 조회·목록형 조회는 `rag_db` 패키지 고객사의 챗봇에서만 열린다. 지금의 에이전시 요금제 검사(`assertDbKnowledgeAllowed`)를 고객사 계약 검사로 바꾼다.
- 월 대화 세션 한도는 고객사 계약 값으로 센다. 에이전시 합계 한도는 엔터프라이즈 상한으로만 남긴다.
- `free_until`이 지나도 챗봇은 바로 멈추지 않는다. 만료 30일 전·당일에 에이전시 업무 홈과 마스터 콘솔에 표시하고, 연장 여부는 수동으로 처리한다(유료 전환 정책이 정해지면 후속).
- 계약이 없는 기존 고객사는 지금처럼 에이전시 요금제를 따른다(이관 기간).

### 4.3 화면

- 마스터 콘솔: 에이전시별 고객사 계약 목록(패키지·설치비·무료 종료일·상태), 계약 추가·수정.
- 에이전시 고객사 상세: 패키지와 무료 종료일 표시(수정은 마스터만).
- 590,000원 패키지 고객사의 DB 섹션: "RAG AI 챗봇 + DB 연동 패키지에서 쓸 수 있어요" 안내.

### 4.4 인수 테스트

| 번호 | 시나리오 | 기대 |
| --- | --- | --- |
| P1 | `rag` 고객사 챗봇에서 DB 연결 추가 | 403, 화면 안내 |
| P2 | 고객사 A 대화가 한도 도달 | A만 한도 안내, 같은 에이전시 B는 정상 |
| P3 | 무료 종료 30일 전 | 업무 홈·마스터에 만료 예정 표시 |
| P4 | 계약 없는 기존 고객사 | 지금 요금제 규칙 그대로 |

## 5. 운영 배포 (DB 연동을 운영에 올리기)

DB 지식 연동·실시간 조회·예시 질문 칩은 통합 브랜치 `codex/db-knowledge`에만 있다. 790,000원 패키지를 Beta로라도 열려면 먼저 아래가 필요하다.

1. 통합 브랜치를 `main`에 머지(사용자 승인 후).
2. 운영 환경변수: `CRON_SECRET`(자동 동기화), `DATA_CONNECTION_EGRESS_IPS`(연결 요청서에 안내할 우리 서버 IP). `DATA_CONNECTION_ALLOW_HOSTS`·`EMBEDDINGS_FAKE`는 운영에 두지 않는다.
3. 고정 IP: Vercel 기본 환경은 나가는 IP가 고정되지 않는다. 고객사 방화벽이 IP 허용을 요구하면 Vercel 고정 IP 옵션 또는 고정 IP 프록시가 필요하다.
4. 매시간 동기화: Vercel Hobby 크론은 하루 1회라 "매시간"은 Pro 요금제 또는 외부 스케줄러가 필요하다.
5. 실제 OpenAI 키로 1회 확인: 모델이 질문에 맞는 조회를 고르는지, 넓은 질문에 안내와 칩이 붙는지.

## 6. 맞춤 설정 (우리가 고객사 DB를 대신 설정)

790,000원 패키지는 "고객사별 맞춤 설정"을 포함한다. 화면은 이미 있으므로 절차와 권한을 정한다.

- 접속 정보는 고객사(또는 호스팅 업체)가 **읽기 전용 계정**으로 만들어 연결 요청서 링크로 전달하고, 고객사 관리자나 에이전시가 화면에 직접 입력한다. 우리 운영자는 채팅·메일로 비밀번호를 받지 않는다.
- 맞춤 설정 작업은 에이전시 계정(고객사 관리 권한)으로 한다. 마스터가 고객사 데이터 연결을 직접 여는 기능은 만들지 않는다.
- 설정 체크리스트: 쓸 표 고르기 → 개인정보 컬럼 제외 확인 → 조회 3개 이하 등록(단건·목록형) → 테스트 값 5개로 확인 → 예시 질문 등록 → 고객사 담당자와 위젯에서 함께 확인.
- 설정 결과(어떤 표·조회를 열었는지)는 감사 기록과 고객사 상세에 남는다.

## 7. 오류 기록

설치비만 받는 구조에서는 장애를 빨리 찾는 게 운영비를 줄이는 길이다.

- `error_logs` 표: 시각, 위치(서버 경로 또는 위젯), 에이전시·고객사·챗봇, 오류 종류, 짧은 메시지, 횟수. 대화 원문·개인정보·비밀값은 넣지 않는다.
- 위젯: API 실패·스크립트 오류를 우리 서버로 보내 같이 쌓는다(분당 상한).
- 마스터 콘솔에 최근 7일 오류 목록과 챗봇별 건수. 30일 후 삭제.
- 알림·스택 추적이 필요해지면 Sentry를 후속으로 더한다.
