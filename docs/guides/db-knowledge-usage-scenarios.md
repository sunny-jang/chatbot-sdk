# DB 지식 연동 — 사용 시나리오

고객사 DB의 표를 연결하면 행 하나가 챗봇 문서 하나가 되고, 정한 주기로 바뀐 행만 다시 가져옵니다. 이 문서는 누가, 어떤 순서로, 무엇을 하게 되는지를 실제 화면 흐름대로 적은 것입니다. (기술 설계는 [PRD](../PRD-db-knowledge-source.md), 검사 항목은 [테스트 시나리오](../qa/test-scenarios-db-knowledge.md))

등장인물: **에이전시 담당자**(우리 고객, 여러 고객사의 챗봇을 운영) · **고객사 관리자**(예: 달빛 카페 사장님) · **호스팅 업체/개발사**(고객사 DB를 관리하는 쪽) · **방문자**(고객사 홈페이지 손님) · **마스터**(우리 운영팀)

예시 고객사: 달빛 카페 — 메뉴·가격·선물세트가 카페 주문 시스템 DB의 `menu` 표에 있다.

---

## 1. 처음 연결하기 — "DB 접속 정보가 없어요"

> 상황: 카페 사장님은 DB 비밀번호를 모른다. 주문 시스템은 호스팅 업체가 관리한다.

1. 고객사 관리자가 데스크 **고객사 설정 → 데이터 연결**을 연다. "아직 데이터 연결이 없어요" 안내와 함께 **연결 요청서** 버튼이 보인다.
2. **연결 요청서**를 열어 링크를 호스팅 업체에 보낸다. 요청서에는 필요한 권한(읽기 전용), 우리 서버 IP, PostgreSQL·MySQL 읽기 전용 계정을 만드는 예시, 회신할 항목(호스트·포트·DB 이름·사용자·비밀번호)이 한 장으로 정리돼 있다. 로그인 없이 열린다.
3. 호스팅 업체가 읽기 전용 계정을 만들고 방화벽에서 우리 IP를 허용한 뒤 접속 정보를 회신한다.
4. 관리자가 **연결 추가**에서 DB 종류(PostgreSQL / MySQL·MariaDB — 종류를 바꾸면 기본 포트가 5432↔3306으로 바뀜)와 회신받은 값을 넣고 **연결 테스트**를 누른다.
5. "연결됐어요 · 테이블 N개"와 표 목록이 뜨면 **연결 저장**. 비밀번호는 암호화돼 저장되고 다시 보이지 않는다(수정할 때 비워 두면 기존 비밀번호 유지).

에이전시 담당자가 대신 해도 된다: 에이전시 **고객사 관리 → 달빛 카페** 화면의 같은 "데이터 연결" 섹션에서 똑같이 한다.

**막히는 경우 — 화면에 뜨는 안내**

| 상황 | 안내 |
| --- | --- |
| 비밀번호 오타 | 비밀번호가 틀렸어요. 사용자 이름과 비밀번호를 다시 확인해주세요. |
| 방화벽이 막음 | 서버가 연결을 거부했어요(또는 시간 초과). 방화벽에서 우리 서버 IP(…)를 허용해주세요. |
| DB 이름 오타 | 데이터베이스 이름을 찾지 못했어요. |
| 사내 IP·localhost 입력 | 내부 또는 제한된 주소로는 연결할 수 없어요. 공개 주소를 입력해주세요. |
| 무료 요금제 | 무료 요금제에서는 DB 연동을 쓸 수 없어요(섹션에 처음부터 안내, 추가 버튼 없음). |

## 2. 메뉴 표를 챗봇 지식으로 만들기

> 상황: 연결은 됐다. 이제 `menu` 표를 "달빛 카페 안내" 챗봇이 읽게 하고 싶다.

1. **챗봇 관리 → 달빛 카페 안내 → 지식 문서** 탭의 **DB에서 가져오기 → 테이블 추가**.
2. **① 연결과 테이블** — 연결 "달빛 카페 메뉴 DB", 테이블 `menu · 약 16행` 선택.
3. **② 컬럼 역할** — 컬럼 이름과 값을 보고 역할을 미리 채워 준다. 틀린 것만 고친다.
   - 제목 `name`(문서 제목), 고유키 `id`(바뀐 행을 찾는 용도), 본문 `category·price·description·is_active`, 제외 `updated_at`.
   - 라벨·단위가 한글로 채워진다(`price` → 가격·원). `is_active`는 "1=판매중, 0=품절"로 값 바꾸기가 들어가 있다.
   - 고객 이름·전화·이메일·주소 같은 컬럼은 "개인정보 추정"으로 표시되고 기본 제외. 일부러 본문에 넣으면 빨간 경고가 뜬다.
4. **③ 가져올 범위** — "+ 조건 추가"로 `is_active 같음 1`(판매중만). 저장할 폴더, 다시 가져오는 주기(기본 매일 새벽).
5. **④ 답변 미리보기** — 앞 3행이 어떤 문서가 되는지 보여 준다.
   ```
   menu: 아메리카노
   분류: 커피
   가격: 4,500원
   판매 상태: 판매중
   설명: 에스프레소에 뜨거운 물을 더한 기본 커피.
   ```
   제안된 질문("아메리카노 가격이 얼마예요?" 등)에 어떤 문서가 근거로 쓰이는지, OpenAI 키가 있으면 짧은 답까지 확인한다. 이상하면 ②로 돌아가 고친다.
6. **저장하고 가져오기** — 진행 막대 `N/M`이 차고 "가져오기를 마쳤어요. 반영 15"가 뜬다. 문서 목록에 **DB** 배지가 붙은 문서 15개가 생긴다.

## 3. 방문자가 묻는 질문

> 상황: 카페 홈페이지의 챗봇 위젯에서 손님이 묻는다.

| 손님 질문 | 챗봇이 하는 일 | 답 예시 |
| --- | --- | --- |
| 아메리카노 얼마예요? | 메뉴 행 문서를 찾아 답 | 아메리카노는 4,500원이에요. |
| 2만원 이하 선물세트 있어요? | "2만원 이하"를 숫자 조건으로 읽어 가격 2만원 넘는 세트는 후보에서 먼저 뺌 → 남은 것 중 가장 가까운 문서 | 원두 선물세트 소(15,000원), 드립백 선물세트(18,000원)가 있어요. |
| 1만~2만원 선물 / 2만원대 세트 / 3천원 미만 디저트 | 범위·○○대·미만도 같은 방식 | — |
| 아몬드 들어간 메뉴 있어요? | 설명 컬럼에 담긴 내용으로 검색 | — |
| 초코 브라우니 있어요? | 품절 행은 범위 조건으로 가져오지 않았으므로 근거 없음 → 지어내지 않고 담당자 연결 안내 | — |

답 아래 **출처 보기**를 펼치면 "등록된 데이터 · 원두 선물세트 소"처럼 근거가 된 행 제목만 보인다. 연결 이름·테이블 이름·원본 값은 방문자에게 보이지 않는다.

## 4. 메뉴가 바뀌었을 때 (자동 동기화)

> 상황: 가격을 올리고, 메뉴 하나를 없애고, 새 메뉴를 추가했다. 사장님은 주문 시스템에서만 고친다.

- 매일 새벽(정한 주기) 자동으로 다시 가져온다. 바뀐 행만 갱신하고 그대로인 행은 건드리지 않는다.
  - 아메리카노 4,500 → 4,800원: 그 문서만 갱신 → 다음 날부터 "4,800원"으로 답.
  - 프리미엄 선물세트 삭제: 문서는 지우지 않고 **보관(검색 제외)** — 문서 목록에 "보관됨 · 검색 제외" 배지. 원본에 다시 생기면 자동으로 보관 해제.
  - 마들렌 추가: 새 문서 생성.
- 소스 목록에 마지막 실행 시각, "반영 0 · 갱신 1 · 변경 없음 13 · 보관 1", 다음 예정 시각이 보인다.
- 급하면 **지금 다시 가져오기**. 주기는 목록에서 바로 바꾼다(수동·매시간·매일 새벽·매주).
- 지워진 행을 문서까지 없애고 싶으면 소스 설정을 "삭제"로 바꾼다(기본은 보관).

주의(화면에도 안내됨): DB에서 가져온 문서를 문서 화면에서 직접 고치면 원본 행이 바뀔 때 다시 덮어쓴다. 내용은 원본 DB에서 고친다.

## 5. 문제가 생겼을 때

| 상황 | 화면 | 할 일 |
| --- | --- | --- |
| 호스팅 업체가 비밀번호를 바꿈 | 자동 동기화가 실패하고 사유 표시. 3번 연속 실패하면 "연속 3회 실패로 자동 동기화를 멈췄어요" + **자동 동기화 멈춤** 배지 | 데이터 연결에서 새 비밀번호로 수정·테스트 → 소스의 **자동 동기화 다시 켜기** |
| 데이터 연결을 지움 | 그 연결의 소스는 "연결 삭제됨"·동기화 중지, 가져온 문서는 보관(답변에 안 씀) | 연결을 다시 만들고 소스를 고치거나, 소스를 삭제(문서 보관/문서까지 삭제 선택) |
| 고유키에 같은 값이 있음(예: category를 고유키로) | "고유키로 고른 컬럼에 같은 값이나 빈 값이 있어요… id 같은 컬럼을 골라주세요" | 행마다 다른 값이 있는 컬럼으로 바꾼다 |
| 행이 너무 많음 | "N행이 상한(5,000행)을 넘어 제외됐어요" | 범위 조건을 좁히거나 소스 상한을 올린다 |
| 요금제 한도에 걸림 | "요금제 한도(에이전시 합계 10,000행)에 맞춰 N행은 가져오지 않았어요" | 요금제를 올리거나 다른 소스를 정리 |
| 화면에서 가져오는 중에 또 누름 | "이미 동기화 중이에요" | 끝날 때까지 기다린다 |

| 요금제 | DB 연동 | 가져올 수 있는 행(에이전시 전체 합계) |
| --- | --- | --- |
| 무료 | 불가(데이터 연결 섹션에 처음부터 안내) | — |
| 그로스 | 가능 | 10,000행 |
| 프로 | 가능 | 50,000행 |
| 엔터프라이즈 | 가능 | 계약값(기본 100,000행) |

## 7. 누가 무엇을 할 수 있나

| 할 일 | 에이전시 소유자 | 고객사 관리자 | 상담 담당자 |
| --- | --- | --- | --- |
| 데이터 연결 추가·수정·삭제 | ○ | ○ | × |
| 연결 테스트·표 목록 보기 | ○ | ○ | × |
| DB 소스 만들기·가져오기·주기 변경·삭제 | ○ | ○ | × |
| 가져온 문서 보기 | ○ | ○ | × |
| 방문자 답변에 쓰인 출처 보기 | 위젯 | 위젯 | 위젯 |

다른 고객사의 연결·소스는 ID를 알아도 열리지 않는다(404).

## 8. 마스터(우리 운영팀)

- 마스터 콘솔 에이전시 목록에 "DB 연결 N · 소스 N · 행 사용량/한도 · 실패 N · 멈춤 N"이 보인다. 건수만 보이고 접속 정보·문서 내용은 보이지 않는다.
- 실패·멈춤이 많은 에이전시에 먼저 연락해 비밀번호 변경·방화벽 문제를 함께 확인한다.

## 9. 지원하지 않는 것(현재)

- 대화 중 실시간 조회("지금 재고 몇 개예요?", "제 주문 어디쯤이에요?") — 매일/매시간 동기화된 값으로만 답한다. 실시간 조회는 데이터 비서 PRD의 후속 범위.
- 엑셀·CSV·Google 시트 연결 — 후속 후보(같은 구조 위에 추가 예정).
- 여러 행을 묶어 문서 하나로 만들기 — 지금은 행 하나 = 문서 하나.
- 상담함(담당자 화면)에서 출처 보기 — 위젯에만 표시.
