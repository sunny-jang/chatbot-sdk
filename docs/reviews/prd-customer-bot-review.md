# PRD 실행 03 — 고객사 관리자 챗봇 작업 공간 작성자 리뷰

## 범위와 권한

- 고객사 관리자/소유자의 자기 고객사 봇 목록, 응대 지침·인사·로고·시간 설정, 문서/Q&A/폴더 CRUD, 문서 파일·XLSX/CSV 가져오기, URL 검토·승인 반영, 설치 코드·실제 위젯 테스트·운영 통계·대화 기록.
- 소유자 전용 생성/삭제/고객사 이동/키/외부 연동/결제는 고객사 관리자에게 제공하지 않는다.
- API마다 인증된 사용자와 URL customer/bot의 관계를 검사한다. knowledge 항목 ID와 폴더 ID도 동일 bot_id 조건을 사용한다.
- 임베딩/파일 추출 같은 외부 작업은 저장 전에 수행하고, 저장 트랜잭션에서 customer→bot 잠금·현재 멤버십을 재확인한다. 권한 회수나 소속 변경이 끼어들면 저장하지 않는다.
- customer/bot 응답은 허용 필드만 선택한다. 공개 설치 토큰은 설치 권한이 있는 관리자에게만 노출한다.

## 리뷰 중 보완

- 기존 에이전시 Q&A 수정/삭제가 항목 bot_id를 누락한 것을 수정. 타 고객사 Q&A ID 변조 HTTP 검사 추가.
- 기존 문서/Q&A 생성 시 폴더의 bot_id 검사와 문서 임베딩의 tenant 키 사용 추가.
- 고객사 간 봇 이동은 기존 소속/대상 고객사를 정렬 잠금 후 상태 재확인. 고객사 작업과 소속 이동이 경합해도 권한 범위를 유지한다.
- 텍스트 입력 요청의 스트림 상한은 기본 12KB를 유지하되 지식 편집만 220KB로 명시 확대. 파일은 전송 중 상한 및 파일별 5MB(로고 2MB)를 적용한다.
- 파일 추출은 기존 파서를 공유한다. 확장자 허용 목록, 본문 길이, Q&A 최대 100건과 필드 검증 후 임베딩. 파일 이름을 경로로 사용하지 않는다.
- URL 가져오기는 기존 SSRF 방어·변경 비교를 재사용하며 preview/apply·메타데이터 저장도 현재 권한을 재확인한다.
- URL 승인 후 문서 목록 갱신 콜백 추가. API 주소 변경을 WebSourceManager의 effect 의존성에 포함.

## 검증과 제한

- 전체 단위 124개, 고객사 DB 39개(모두 롤백), 실제 HTTP 31개 통과.
- HTTP는 관리자 설정·조회·통계·로그·URL 원본 조회, 일반 담당자 거부, 타 봇/Q&A 항목 변조 거부를 포함.
- 브라우저: 고객사 관리자 로그인→자기 봇 목록→설정/문서·URL/통계 화면 확인. 캡처 docs/verification/prd-execution/.
- 타입·빌드 통과. 변경 파일 린트 오류 없음(이미지 요소 경고는 최적화 권고).
- 실제 모델 키를 사용하는 임베딩·대화·URL 승인 전체 왕복과 실제 외부 채널은 환경 검증 대기다. DB 서비스는 합성 벡터로 CRUD·격리/감사를 검사했다.
- 실제 위젯 테스트는 기존 방식으로 테스트 대화가 저장될 수 있음을 화면에 안내한다. 공유 데모의 별도 격리는 다음 데모 PR 범위다.
- 이 PR은 공통 Google 로그인·전체 이관·전체 L01~L18 완료가 아니다.

독립 Codex 리뷰 및 CI 결과는 PR에서 추가 확인한다. 작성자 리뷰만으로 독립 리뷰 통과라고 표시하지 않는다.

## 독립 리뷰 후 수정 (2026-10-22)

- 기존 URL API에서는 고객사 세션을 기본 거부한다. 공통 처리기를 lib로 옮기고, Origin·속도 제한·고객사 권한을 검사한 고객사 경로만 명시적으로 고객사 세션을 허용한다. 저장 시 같은 옵션으로 현재 권한을 재검사한다.
- 에이전시/고객사 Q&A 가져오기는 같은 파서를 사용한다. 제목·안내 행 앞부분, 시트 이름, 질문 없는 답변 이어쓰기와 여러 답변 열을 보존한다. 고객사 100건 제한은 파싱 후 임베딩 전에 검사한다.
- 고객사 문서 업로드는 봇 잠금 아래 같은 제목의 기존 문서를 갱신하거나 동일 본문을 건너뛴다. 반복 업로드가 중복 문서와 오래된 임베딩을 남기지 않도록 한다.
- 추가 검증: 단위 126건, DB 42건(전체 롤백), 프로덕션 빌드 성공. 재업로드 동일 ID·동일 본문 건너뛰기·변경 본문 갱신·담당자 거부와 기존 엑셀 형식 회귀 검사를 포함한다.

### 재리뷰 추가 보완

동일 문서는 잠금·권한 확인 후 임베딩 전에 건너뛰고, 변경 문서는 임베딩 이후 저장 잠금 아래 다시 비교한다. Q&A 재가져오기는 봇·질문 기준 갱신으로 기존 ID를 유지한다. 대상 폴더를 명시하지 않으면 시트 이름별 폴더를 생성/재사용한다.

추가 DB 검사 포함 45건, 프로덕션 빌드·타입·변경 파일 린트 통과. 모델 키 없는 QA 환경의 실제 multipart 동일 문서 업로드 검사 포함 HTTP 32건 통과. HTTP 첫 실행은 앞선 검사가 닫아둔 QA 상담 상태 때문에 동시 수락·전송 2건 실패했고, fixture 초기화 후 전체 재실행에서 32건 통과했다. 실제 모델 왕복 검증은 여전히 미실행이다.

### 기존 봇 호환·폴더 UI 보완 (2026-10-23)

고객사 미배정 기존 봇의 에이전시 URL 미리보기/승인 저장은 tenant→bot 잠금으로 기존 소유권을 재확인한다. 잠금 중 고객사에 배정됐다면 409로 재시도를 요청한다. 고객사 세션은 보호된 경로의 명시적 위임만 허용하는 기존 제한을 유지한다.

문서/Q&A 모두 등록 폴더 이름 변경·삭제 UI를 추가했다. 삭제 확인과 내용은 미분류로 유지된다는 안내를 제공한다. 브라우저에서 합성 폴더 생성→이름 변경→삭제 확인→목록 제거 검수. 캡처 customer-folder-controls.png. 실제 공개 페이지를 가져온 미배정 봇 미리보기 저장 포함 HTTP 33건 통과. 프로덕션 빌드 통과.

### 재리뷰 보완: 기본 위젯 색상·동일 문서 폴더 이동 (2026-10-23)

- 고객사 설정 저장 폼은 `widget_color`가 비어 있는 기존 봇에 공개 위젯·에이전시 설정과 같은 `DEFAULT_WIDGET_COLOR`(#2563eb)를 보낸다. 이름이나 인사말만 바꿔도 실제 위젯 색이 바뀌지 않는다.
- 같은 제목·같은 본문 문서를 다른 폴더로 다시 업로드하면 임베딩 호출 없이 봇 잠금 아래 대상 폴더의 bot_id를 검사한 뒤 `folder_id`만 갱신한다. 응답은 `skipped: true`에 `moved` 여부를 함께 돌려주고 `knowledge.put` 감사 기록을 남긴다. 임베딩 후 저장 잠금에서 다시 비교하는 경로도 같은 처리를 한다.
- 추가 DB 검사: 폴더 이동·같은 폴더 재업로드는 `moved: false`·미분류 복귀·다른 봇 폴더 404·감사 기록 수. DB 46건 롤백 통과, 단위 126건, `tsc --noEmit` 통과, 변경 파일 린트 0오류(기존 img 경고 1).

### 독립 리뷰 2차 (2026-10-23, Claude code-review — Codex 사용량 한도로 대체)

Codex 리뷰 봇이 사용량 한도 초과로 `failed`를 돌려줘 별도 리뷰 에이전트로 8건을 받아 모두 반영했다.

- `adminBot`: 에이전시 세션의 잠금 경로에서 `portalUser`/`customerBot`이 던지는 PortalError가 500으로 뭉개지던 것을 모든 경로에서 OperationError로 변환. 고객사 경로는 `resolveBotAccess`+`customerBot`+봇 재조회 3중 확인을 봇의 customer_id 조회 후 `customerBot` 1회로 줄였다.
- 에이전시 `PUT /api/bots/[id]/qa/[qaId]`: `COALESCE(folder_id || null, folder_id)` 때문에 빈 folder_id로 미분류 이동이 불가능하던 것을 `folder_id === undefined`일 때만 유지하도록 수정.
- 공유 워크북 파서: 답변 뒤의 `비고·담당자·수정일·메모` 등 관리용 열이 답변에 합쳐지던 것을 건너뛴다(기존 `추가` 같은 임의 열은 답변으로 유지). 7개 시트 초과분을 조용히 버리지 않고 30개까지 읽고 건너뛴 시트 이름을 응답에 포함. 각 행의 시트 행 번호(`line`)를 돌려줘 고객사 가져오기 오류에 `시트명 N행:`을 붙인다. 단위 검사 3건 추가.
- `importCustomerQa`: 행마다 `customerBot` 재잠금·재검사·감사 행을 남기던 것을 봇 잠금 1회, 시트 폴더 1회 생성/재사용, 직접 upsert, `knowledge.import` 감사 1건으로 정리. 응답에 created/updated 수 포함. 기존 DB 회귀(ID 유지·시트별 폴더) 통과.
- HTML 업로드: 정규식 태그 제거 대신 cheerio로 `script/style/noscript/template` 본문을 제거하고 블록 요소 사이 공백을 보존. 단위 검사 추가.
