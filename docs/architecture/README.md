# 데이터베이스 ERD

- [대화형 HTML](chatbot-erd.html): 테이블 선택, 관계 강조, 전체 컬럼, 확대·축소
- [SVG](chatbot-erd.svg): 편집·문서 첨부용
- [Mermaid](chatbot-erd.mmd): 관계도 소스
- [스키마 스냅샷](schema-2026-10-22.json): 컬럼, 기본키, 외래키, 유일 제약조건

2026-10-22 격리된 로컬 QA DB의 실제 PostgreSQL public 스키마를 읽었습니다. 35개 테이블, 56개 외래키 제약조건(복합키를 풀면 58개 컬럼 관계)입니다. 고객사 권한 및 공유 데모의 개발 중 마이그레이션을 포함합니다. 운영 DB에 적용됐다는 의미가 아닙니다.

계정·고객사, 챗봇·지식, 상담·접수, 운영·연동, 공유 데모의 다섯 영역으로 구분했습니다. FK가 선언되지 않은 논리 관계는 추정해서 그리지 않았습니다. Mermaid의 관계 수는 실제 FK 제약조건 단위이며, 필수 여부와 자식 쪽 유일 제약조건을 반영합니다. SVG는 관계 방향을 표시하고 전체 컬럼은 HTML에서 확인합니다.

내보내기는 메타데이터만 읽습니다. 고객 데이터, 대화 내용, 토큰 및 API 키 값은 포함하지 않습니다. 실제 컬럼 이름은 그대로 보존합니다.

## 재생성

저장소 루트에서 승인된 검증 DB의 환경 파일을 지정합니다. 환경 파일을 커밋하거나 내용을 출력하지 마세요.

```sh
node --env-file=/path/to/qa.env --import tsx scripts/export-erd.ts
python3 scripts/render-erd.py
```

현재 파일명과 표시 날짜는 스냅샷 날짜로 고정돼 있으므로 새 스냅샷을 만들 때 두 스크립트의 날짜도 함께 갱신합니다. HTML은 외부 라이브러리나 네트워크 연결 없이 열 수 있습니다.

신규 테이블이 기존 분류에 없으면 ‘기타 테이블’ 영역에 자동 배치하고 도면 폭을 확장합니다. 재생성 회귀 검사는 `python3 tests/erd-renderer.test.py`로 실행합니다. FK가 있는 신규 테이블과 독립 테이블 모두 SVG에 존재하는지 확인합니다.
