# 운영 화면 개편

작성: 2026-10-16

## 목표

중소 사업장의 담당자가 상담과 챗봇 관리를 함께 할 수 있게 한다. 파트너는 여러 고객사를 관리하고, 마스터는 플랫폼 운영을 맡는다. 기존 설치·대화·요금제 데이터는 유지한다.

## 단계와 완료 기준

1. 업무 화면 정리: 실제 데이터의 업무 홈, 대기 우선 상담함, 통합 문의·견적 목록, 독립 챗봇 목록, 모바일 메뉴, 요금제 접근. 기존 모든 봇별 기능은 유지. 오류·빈 상태·중복 전송·대화 전환 중 오래된 응답 노출을 확인.
2. 고객사·구성원 권한: 파트너 소유 고객사, 봇 연결, 초대 수락·만료·취소, 고객사 관리자/담당자. 모든 조회·수정·내보내기·상담 API에 고객사 범위 검사. URL 직접 접근과 다른 고객사 ID 교체 차단 테스트. 작은 사업장은 한 사람이 두 역할을 겸한다. 화면 전환은 권한 검사를 대신하지 않는다.
3. 가입·요금제 연결: 현재 가입 시 생성되는 tenant를 파트너 공간으로 활용. 기존 플랜의 봇·세션 한도를 유지하고 고객사/구성원 한도는 상품 결정 후 적용. 기존 고객사·봇 이관은 사전 매핑과 복구 가능한 절차로 처리.
4. 고객사 데모: 사이트 배경 + 실제 위젯. iframe 차단 시 대체 미리보기. 공유 링크 만료·해제, 운영 대화와 테스트 구분.
5. 먼저 말 걸기 운영: 표시·클릭·대화 전환 지표, 기본 인사와 AI 제안, 조건·월 한도 조절.

## 정보 구조

- 업무: 업무 홈 / 상담함 / 문의·견적
- 관리: 챗봇 관리 / 이용 현황 / 공간 설정 / 요금제
- 도움: 이용 가이드 / 설치 가이드
- 마스터 전용: 플랫폼 관리 (서버 관리자 권한 유지)
- 선택한 봇: 설정·설치 / 지식 문서 / Q&A / 테스트 / 대화 기록 / 문의·견적 / 분석

## 화면 원칙

색상: 본문 #17243b, 보조 #59677d, 배경 #f3f6fb, 표면 #ffffff, 강조 #4059d8, 대기 #a65f08.
글꼴: 기존 Geist와 한국어 시스템 글꼴. 본문 14px 이상, 목록 본문 14~15px, 주요 수치 28px, 제목 26~30px. 왼쪽 정렬.
업무 홈은 작업 대기 목록을 중심으로 구성하며 상담 대기와 신규 문의를 먼저 보여준다. 상담 화면은 왼쪽 목록, 오른쪽 대화로 배치하고 모바일에서는 한 영역씩 표시한다.

    메뉴 | 업무 홈             메뉴 | 상담함
         | 상담 대기 / 신규 문의     | 필터·목록 | 고객 대화
         | 처리할 업무              |           | 인계 요약
         | 챗봇 바로가기            |           | 답변 작성

## 구현 범위 주의

첫 단계는 기존 tenant 내부의 동선 개편이다. 고객사별 로그인과 담당자 권한이 구현되기 전에는 제공된다고 안내하지 않는다. 상담 대기 수는 전체 합계와 페이지에 표시한 목록 수를 구분한다. 데이터가 없으면 가짜 수치 대신 실제 빈 상태를 표시한다.

## 1차 구현 결과

- 업무 홈: 실제 대기·진행 상담 수, 신규 신청 수, 챗봇 수. 오래된 대기 상담/미처리 신청 각 5건과 최근 챗봇 바로가기.
- 기존 챗봇 목록은 `/bots`로 이동. 기존 봇별 URL과 설정·문서·테스트·기록·분석은 유지.
- `/requests`: tenant 범위 내 문의·견적 통합, 상태·이름·내용 검색, 최근 100건, 기존 상세 관리로 연결.
- 상담함: 대기 우선·오래된 요청 우선, 상태 탭·검색, 대화별 초안, 전송 실패 시 초안 유지, 다른 대화로 전환하면 이전 조회 취소, 서버 오류 표시, 모바일 목록/대화 전환.
- 메뉴: 업무·관리·도움말·마스터 전용 구분. 좁은 화면은 접을 수 있는 메뉴. 마스터 메뉴는 기존 관리자 판정 유지.
- 현재 이 구현은 로컬 검증 및 검토 단계. 고객사별 초대·로그인은 후속 로컬 구현이 추가됐으나 미배포이며, 고객사 홈페이지 데모는 미구현.

## 개발팀 검증

실행·데이터 준비·수동 시나리오·자동 테스트·결과 기록은 [개발팀 테스트 가이드](qa/workspace-redesign-test-guide.md)를 따른다. 작성자 검증과 개발팀의 독립 검증 결과를 구분한다.

## 2차 상세 기획

상담 담당자별 로그인·초대·고객사 권한은 [상담 담당자 로그인 PRD](PRD-agent-login-and-customer-access.md)를 기준으로 구현한다. 신규 상담 포털은 일부 로컬 구현됐으며 전체 인수·운영 이관은 미완료다.


## 2026-10-22 검수

현재 기능별 상태·누락·인수 근거는 [PRD 대비 구현 검수](reviews/prd-implementation-audit-2026-10-22.md)를 따른다. 5단계 전체 완료가 아니며 고객사 데모는 미구현이다.
