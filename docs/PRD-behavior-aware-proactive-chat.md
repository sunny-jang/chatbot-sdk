# PRD: 행동 기반 AI 먼저 말 걸기

- 작성일: 2026-10-15
- 상태: MVP 구현. 아래는 목표 기획이며 실제 구현 범위·검증은 `PROACTIVE-WIDGET.md`의 AI 제안 항목을 참고한다.
- 대상: 설치형 웹사이트 챗봇. 작은 사업장의 방문 고객과 설치를 지원하는 웹에이전시.
- 목표: 위젯 설치만으로 방문자가 머무는 콘텐츠 구간을 감지하고, 상담·영업 직원처럼 부담 없는 질문으로 상황을 확인한 뒤 맞는 서비스를 안내한다.
- 개정: 스크롤 중심 콘텐츠 구간 분석과 상담형 대화 흐름을 핵심으로 반영.

## 1. 현재 구현과 변경 범위

현재 `public/chatbot-widget.js`는 페이지 경로·이동·보이는 탭의 체류·클릭 종류·스크롤을 자동 감지한다. 최근 12개 이벤트를 현재 탭의 sessionStorage에 보관하며, 서버나 AI에 보내지 않는다. 설정 시간 후 고정 문구를 한 번 표시한다.

추가할 기능은 행동을 요약해서 제한적으로 AI에 전달하고, 등록된 업체 자료를 근거로 **제안할지 / 무엇을 제안할지 / 어떤 대화를 시작할지**를 결정하는 것이다. 대기 시간을 줄이는 것만으로 행동 분석이라고 표현하지 않는다.

## 2. 제품 경험

관리자 설정은 다음 세 가지 모드로 구분한다.

| 모드 | 수집·동작 |
|---|---|
| 끄기 | 먼저 말 걸기용 행동 수집과 분석 중단 |
| 기본 인사 | 설정 시간 후 관리자 문구 표시. AI 호출 없음 |
| 상황별 AI 제안 | 자동 행동 요약과 업체 지식을 사용해 필요한 제안만 표시 |

기존에 활성화된 챗봇은 기본 인사 모드를 유지한다. 상황별 AI 제안은 관리자가 별도로 선택한다. 비용·요약 전송·설정 반영 시점을 설정 화면에서 안내한다.

방문자에게는 채팅 버튼 옆에 짧은 제안과 닫기 버튼을 제공한다. 채팅창을 강제로 열지 않으며, 자동으로 견적을 접수하거나 상담원에게 메시지를 보내지 않는다.

### 상담·영업 직원처럼 다가간다

기본 흐름은 **관심 구간 감지 → 맥락 있는 첫 질문 → 고객 답변으로 상황 확인 → 업체 자료에 근거한 서비스 안내 → 원할 때 상담 접수**다. 콘텐츠 요약과 서비스 비교는 상담 과정에서 필요한 도구이며, 첫 접근의 기본 목적이 아니다.

| 화면에서 충분히 노출된 콘텐츠 | 먼저 하는 말 | 동의한 뒤의 다음 질문 |
|---|---|---|
| RAG 챗봇·고객 응대 자동화 설명 | 고객 문의 응대를 자동화하려고 알아보시는 걸까요? | 지금은 홈페이지 문의를 직접 받고 계세요, 아니면 다른 상담 채널을 쓰고 계세요? |
| 업무 자동화 설명 | 반복되는 업무를 줄일 방법을 찾고 계신가요? | 어떤 업무에 가장 시간이 많이 드세요? |
| 사내 지식 검색 설명 | 직원들이 회사 자료를 찾는 데 시간이 많이 드나요? | 주로 어떤 자료를 찾으시나요? |
| 두 서비스 구간을 충분히 보고 다시 돌아옴 | RAG 챗봇과 AI 자동화 중 어떤 쪽이 맞을지 함께 살펴볼까요? | 해결하려는 업무를 짧게 말씀해주실 수 있을까요? |
| 구간들을 빠르게 지나감·관련 지식 없음 | 제안하지 않음 | 기본 채팅 버튼 유지 |

예시는 해당 서비스·자료가 실제 등록돼 있을 때의 목표 동작이다. 관심 구간에 머물렀다는 이유만으로 도입 의도나 업무 문제를 사실처럼 단정하지 않는다.

### 첫 질문과 상담 원칙

- 고객사마다 실제 서비스와 해결 가능한 문제를 기준으로 질문한다. 아무 사이트에나 붙이는 일반 문구를 상황별 AI 제안이라고 부르지 않는다.
- 대상 서비스 이름을 자연스럽게 사용할 수 있지만, 모든 첫 질문에 이름을 억지로 삽입하지 않는다. 실제 주제와 고객에게 물어볼 문제의 연결이 중요하다.
- “오래 보고 계시네요”, “세 번 돌아오셨네요” 같은 추적 표현을 쓰지 않는다.
- 질문은 한 번에 하나. 연락처·예산·구매 시기를 처음부터 한꺼번에 요구하지 않는다.
- 고객이 상황을 말하면 이미 확인한 정보는 반복 질문하지 않는다. 답변과 추천의 이유를 짧게 연결한다.
- 탐색·정보 확인만 원하는 고객에게 접수를 강요하지 않는다. 거절하면 일반 질문으로 전환한다.
- 실제 지원하지 않는 기능과 자료에 없는 가격·납기·성과를 약속하지 않는다.

### 상담 예시

1. 말풍선: “고객 문의 응대를 자동화하려고 알아보시는 걸까요?”
2. 고객이 말풍선 클릭: 질문을 채팅에 그대로 이어서 표시하고, “네, 알아보고 있어요 / 다른 내용이 궁금해요” 또는 자유 답변으로 의도를 확인한다. 클릭 자체를 ‘네’라고 해석하지 않는다.
3. 고객: “네. 홈페이지 문의를 혼자 받아요.”
4. AI: “어떤 문의가 가장 자주 들어오나요?”
5. 고객: “서비스 가격이랑 진행 기간이요.”
6. AI: 등록 자료에서 확인되는 챗봇의 답변·접수 범위를 설명하고, 고객의 반복 문의와 맞는 이유를 안내한다.
7. 고객이 원할 때 상담에 필요한 내용을 정리하고 접수로 연결한다. 가격이나 기간 근거가 없다면 담당자 확인이 필요하다고 설명한다.

## 3. 자동 수집과 페이지 이해

### 브라우저에서만 유지하는 행동

- 방문 순서, 페이지별 보이는 탭 체류 시간, 재방문 횟수.
- 링크·버튼 클릭 종류: 서비스, 가격, 문의, 기타 이동.
- **콘텐츠 구간별 화면 노출 시간·다시 진입한 횟수·최근 머문 구간·이동 순서.** 스크롤 픽셀만으로 관심 내용을 추측하지 않는다.
- 제안 노출·닫기·클릭, 직접 채팅 시작 여부.
- 최근 이벤트 최대 12개와 관련 구간 최대 6개. 페이지 변경 시 구간 상태도 갱신한다.

설치 외에 HTML 속성 추가나 버튼·구간 지정을 요구하지 않는다. 자동 식별이 실패한 사이트에서는 페이지 수준 신호로 낮추거나 상황별 제안을 생략한다.

### 콘텐츠 구간 자동 감지

1. `main`, `article`, `section`, 제목(h1~h3)과 주변 공개 본문을 기준으로 의미 있는 구간을 자동 구성한다.
2. 메뉴·푸터·광고·위젯 자체·폼·입력값·숨겨진 요소·개인정보 영역은 제외한다.
3. IntersectionObserver로 구간의 실제 화면 노출을 관찰하고, 보이는 탭에서 스크롤이 안정된 시간을 누적한다. 화면보다 긴 구간은 전체 요소 비율 대신 화면 내 노출 면적으로 판단한다.
4. 현재 화면에서 가장 의미 있게 노출된 구간을 주 관심 후보로 둔다. 빠른 통과와 짧은 왕복은 관심으로 인정하지 않는다.
5. SPA 이동·뒤로 가기·접힌 콘텐츠 펼침·지연 로딩을 반영한다. MutationObserver는 debounce하고 탐색 요소·텍스트량을 제한해 사이트 성능을 해치지 않는다.
6. 공개 구간 제목과 필터링한 짧은 설명을 기존에 등록된 업체 지식과 연결한다. 화면 내용은 고객의 관심 주제를 찾는 힌트이며, 그 자체로 승인된 판매 정책이 되지 않는다.

초기 실험안: 화면 높이의 25% 이상을 차지하거나 제목과 본문이 함께 보이는 구간, 누적 노출 10초 이상을 후보로 고려한다. 이 수치는 파일럿에서 조정하며 읽었다고 보장하지 않는다. 자동 분할이 애매하면 오탐 제안보다 생략을 우선한다.

### 페이지 분류

경로만으로는 `/blog/8`이 어떤 글인지 알 수 없다. 등록된 공개 사이트 자료의 URL·제목·주제를 연결한 페이지 지도를 사용한다. URL에서 쿼리와 fragment를 제거하고, 허용된 사이트의 등록된 자료와 매칭한다.

- 지도에 있는 페이지: 내부 pageId, 짧은 공개 제목, 유형·주제를 사용.
- 지도에 없는 페이지: 개인정보 필터를 통과한 공개 제목과 링크 분류로 제한적으로 분류. 제목이 민감하거나 판단이 불명확하면 `unknown` 처리.
- 폼·로그인·회원·결제·계정 페이지는 상세 의미 추출 대상에서 제외. 모르는 페이지에서는 고객 상황을 구체적으로 단정하지 않음.
- 행동 분석 API가 방문자의 임의 URL을 즉석에서 fetch하지 않도록 한다. 기존에 승인·수집한 공개 자료를 재사용한다.

### 서버와 모델에 전송하는 요약

원본 클릭 로그 대신 최대 6개 관련 구간의 pageId/sectionId, 공개 제목, 필터링한 설명(구간당 최대 200자), 주제, 노출 시간 구간, 재진입 여부, 최근 순서, 현재 관심 구간과 클릭 종류별 횟수를 보낸다. 개인화 페이지·로그인 영역은 본문 추출 및 전송에서 제외한다. IP·연락처·입력값·URL 쿼리·전체 DOM·화면 캡처·마우스 좌표는 모델에 보내지 않는다. pageId를 만들 수 없는 경로는 전송을 최소화하고 민감 경로를 제외한다.

방문 단위 데이터이며 브라우저 간 식별, 로그인 고객 프로파일, 장기 관심사 추적은 MVP 범위 밖이다. 사이트 운영자가 필요한 안내와 데이터 전송 설정을 제공할 수 있도록 준비하며, 법적 요구사항은 실제 제공 지역과 수집 설계에 맞춰 별도로 검토한다.

## 4. 제안 시점: 규칙으로 좁히고 AI로 결정

매 클릭마다 AI를 부르지 않는다. 브라우저가 후보를 찾고 서버가 다시 검증한 후 호출한다.

초기 실험용 후보 조건은 다음과 같다. 출시 효과를 검증한 수치가 아니며, 실제 결과로 조정한다.

| 후보 | 제안 분석 조건 |
|---|---|
| 서비스 관심 | 알려진 서비스 구간에서 누적 노출 5초 이상 + 누적 방문 체류 30초 이상 |
| 서비스 선택 고민 후보 | 같은 페이지 또는 다른 페이지의 서로 다른 서비스 구간 2개 이상에서 각각 10초 이상 + 구간 재진입 + 누적 30초 이상 |
| 비용·문의 관심 | 알려진 가격/문의 구간 노출 5초 이상 또는 관련 클릭 + 누적 30초 이상 |
| 주제 탐색 | 동일 주제의 서로 다른 구간·공개 자료 2개 이상 + 누적 45초 이상 |

시간은 숨겨진 탭을 제외한다. 빠른 연속 이동에는 분석하지 않는다. 클릭·이동·스크롤 후 최소 3초 동안 화면이 안정된 뒤 후보를 평가한다. 키 입력 중이나 폼 조작 중에는 제안을 보류한다.

조건을 통과해도 AI는 `제안하지 않음`을 선택할 수 있다. 충분한 정보가 없으면 도움을 꾸며내지 않는다.

### 공통 제한

- 직접 채팅을 열었거나 이번 방문에서 대화를 시작했으면 자동 제안 중단.
- 상담원 연결 대기·진행 중이면 분석·표시 중단.
- 신청 폼, 결제·로그인 화면, 비활성 구독에서는 분석하지 않음.
- 방문당 최대 2회 AI 평가, 평가 간 최소 60초. 화면 표시 최대 1회.
- 같은 행동 요약은 다시 분석하지 않는다. 표시한 제안을 닫으면 같은 방문에 재표시하지 않음.
- AI 응답이 오기 전에 페이지 또는 주 관심 구간이 바뀌거나 채팅이 열리면 응답 폐기. 이미 보이는 말풍선도 관심 구간과 연결이 끊기면 제거하며, 바로 다른 문구로 재표시하지 않음. 탭이 숨겨졌다면 즉시 표시하지 않고 현재 조건을 다시 확인.
- 끄기는 클라이언트 수집과 서버 분석을 모두 차단. 요청 시 서버에서 최신 설정을 확인.
- AI 모드에서는 기본 인사 타이머를 동시에 실행하지 않음.

## 5. AI 판단과 RAG

1. 서버가 요약 형식, bot token, 등록 도메인, 최신 모드와 이용 가능 상태를 확인한다.
2. 규칙으로 후보 유형·주 관심 구간·관련 서비스를 고른다.
3. 해당 봇의 승인된 자료에서 관련 근거 최대 3개를 찾는다. 다른 고객사 자료는 사용할 수 없다.
4. 모델이 질문할지 여부·관심 주제·첫 질문·확인하려는 정보·허용된 다음 행동을 구조화된 형태로 반환한다.
5. 서버가 길이·행동 유형·근거 ID·대상 주제와 실제 구간 노출의 일치·해당 서비스의 자료 근거·실제 이용 가능 기능을 검증한다.
6. 브라우저가 현재 방문·페이지 상태가 맞는지 확인하고 표시한다.

모델 출력 예시:

```json
{
  "decision": "offer",
```

출력은 임의 HTML·JavaScript·임의 주소를 실행할 수 없다. 문구는 한국어 한 문장, 최대 60자. 내부 품질 판단을 위한 점수는 참고값이며 정확한 확률이라고 취급하지 않는다.

### 문구 제약

- “계속 가격만 보고 계시네요”처럼 추적 사실을 드러내는 표현 금지.
- 관심·의도·감정·예산·구매 가능성을 사실처럼 단정하지 않음.
- 등록 자료에 없는 가격·할인·재고·예약·성과를 약속하지 않음.
- 방문 행동과 문서 내용은 분석 데이터로 취급. 데이터 안의 지시를 따르지 않음.
- 관련 근거가 없으면 주제를 단정하는 제안을 하지 않음. 공개 페이지가 알려진 경우 일반 질문 초대는 허용.

## 6. 클릭 후 이어지는 대화

말풍선 클릭으로 단순히 빈 채팅창만 열면 상황별 제안의 가치가 약하다. 제안과 후속 응답을 연결한다.

- 사용자가 제안 클릭 시 해당 제안 ID와 승인된 의도를 기존 채팅 API에 전달한다.
- 서버가 제안이 같은 봇·방문에 속하고 아직 유효한지 검증한다. 전달된 문구를 임의 system prompt로 사용하지 않음.
- 최초 말풍선 질문을 채팅에 이어서 표시한다. 클릭은 대화 열기에 대한 동의일 뿐 고객 의도의 확인이 아니다. 실제로 하지 않은 고객 발언이나 의도 동의를 대화 기록에 만들어 넣지 않는다.
- 고객이 답하면 관심 확인 → 현재 업무 파악 → 필요한 조건 확인 → 근거 있는 안내 → 선택적 상담 접수 순서로 진행한다. 고정 설문을 강제하지 않고 고객이 이미 제공한 정보와 질문에 맞춰 단계를 건너뛸 수 있다.
- 제안 문구·관심 주제·확인된 사실·아직 확인하지 않은 정보를 구분해 유지한다. 모델이 추정한 관심을 고객이 말한 사실로 저장하지 않는다.
- 고객이 비교를 요청했다면 실제 대상 서비스 비교로 바로 이어가고, 고객 상황을 아직 모르는 첫 상담 질문에서는 먼저 상황을 확인한다.
- 말풍선만 노출하는 단계에서는 채팅 세션 생성·월 대화 세션 차감·신청 저장을 하지 않는다.
- 클릭 후 AI 답변이 시작되면 기존 채팅 이용량 정책을 적용한다.
- 신청 유형이 꺼져 있으면 대화만 시작한다. 켜져 있어도 고객이 제출하기 전에는 접수하지 않음.
- 방문자가 제안을 거절하거나 문의를 바꾸면 일반 대화로 이어짐.

## 7. 비용·요금제 제안

현재 플랜은 무료/그로스/프로/엔터프라이즈이며 챗봇 수와 월 대화 세션 한도를 사용한다. AI 제안 평가를 채팅 세션으로 세면 방문만 해도 한도가 소진될 수 있으므로 별도의 `AI 제안 평가 횟수`를 둔다.

- 기본 인사는 기존 범위 유지.
- AI 제안은 고객사 API 키를 사용하는 구조를 우선 제안. 설정에서 모델 호출 비용이 별도 발생함을 설명.
- 월 평가 한도 + 봇별 분당 제한 + 방문당 제한 + 동일 요약 캐시로 비용 통제.
- 실패한 호출도 provider 비용이 발생할 수 있으므로 호출 시도·토큰·결과를 함께 기록. 한도 예약은 원자적으로 수행.
- 한도 도달·키 없음·시간 초과 시 고정 기본 문구로 한 번 대체. 모드가 꺼진 경우나 문맥상 제안 불필요인 경우에는 대체 문구도 표시하지 않음.
- 가격과 플랜별 평가 한도는 파일럿 비용 측정 후 확정. MVP를 시험하기 위해 임의의 유료 플랜 제한을 기존 계정에 바로 적용하지 않음.
- 파트너/고객사 구조 개편 전에는 현재 tenant 단위로 계산. 개편 후 과금 주체는 따로 확정.

## 8. 관리자 화면

**먼저 말 걸기** 설정에서 모드 선택, 기본 문구, 최소 대기 시간, 민감·제외 페이지 설정을 제공한다. 행동 규칙은 초기에는 자동 기본값으로 두고 관리자에게 복잡한 조건 편집기를 요구하지 않는다.

테스트 도구를 반드시 제공한다. 실제 방문에서는 한 번 표시·대화 시작 후 중단 규칙이 있어 반복 테스트가 어렵다.

- 관리자 테스트 방문 링크: 일반 고객 방문과 분리된 만료 토큰과 test visit ID.
- 방문 상태: 자료 수집 중 / 조건 부족 / 분석 중 / 제안하지 않음 / 표시 / 대화 시작 / 닫힘.
- 이유: 최소 체류 미달, 자료 부족, 이미 노출, 현재 상담 중, 한도 도달 등.
- 행동 요약과 제안 예시 미리보기. 민감 입력값이나 원본 클릭 텍스트는 보여주지 않음.
- 테스트 다시 시작: 테스트 방문 상태만 초기화. 고객 대화나 실제 상담 기록을 삭제하지 않음.
- 운영 위젯에는 진단 패널을 노출하지 않음.

## 9. 기존 구조에 붙이는 방식

| 기존 위치 | 추가/변경 |
|---|---|
| `lib/proactive.ts` | 모드·AI 평가 제한·설정 검증 추가. 기존 enabled 설정 호환 |
| 봇 설정 및 공개 위젯 API | 모드와 공개 가능한 표시 설정 제공. 키와 내부 문서 원문은 제공하지 않음 |
| `public/chatbot-widget.js` | 콘텐츠 구간 자동 분할·노출 시간 요약, 후보 감지, 평가 호출, 취소·표시 상태 관리 |
| 신규 `/api/chat/[botId]/proactive` | 최신 설정·이용량·요약 검증, 자료 조회, 제한된 모델 호출 |
| 기존 채팅 API | 제안 클릭 후 의도와 근거 연결, 정상 대화 기록·이용량 처리 |
| DB | 제안 평가·결과·근거·클릭·닫기 메타데이터. 모델에 보낸 원본 행동 로그는 저장하지 않음 |

전송 크기는 최대 8KB, 페이지 최대 6개, 관련 문서 문맥 총 3,000자, 제안 호출 제한시간 4초를 초기 예산으로 제안한다. 응답 캐시는 봇·자료 버전·설정 버전·행동 요약에 묶어 고객사 간 공유하지 않는다.

새 테이블에는 bot/tenant/visit ID, 평가 ID, 상태, 사용 토큰, 근거 ID, 오류 종류, 노출/클릭/닫기 시간을 기록한다. 방문 원문은 저장하지 않고 집계 목적에 필요한 최소 메타데이터만 보관한다. 초기 메타데이터 보유 기간은 30일 제안이며 설정·정책 검토 후 확정한다.

기존 상담 기록은 삭제하거나 재분류하지 않는다. 기존 DB의 과거 대화와 새 방문의 제안 여부는 별도로 관리한다.

## 10. MVP와 후속 범위

### MVP

1. 기존 설치 코드로 자동 수집 및 기본/AI 모드 구분.
2. 알려진 페이지·구간 지도, 서비스 관심·선택 고민·비용/문의·주제 탐색 후보.
3. 제한된 평가와 RAG 근거로 짧은 제안 생성.
4. 클릭 후 첫 질문을 이어가고 고객 답변으로 상황을 파악하는 상담 흐름, 닫기·반복 제한.
5. 관리자 테스트·진단, 별도 사용량 집계.
6. 아이디얼 테크에서 파일럿.

### 후속

다국어 제안, 운영자가 승인한 상세 조건 편집, 실험 그룹 배정, 페이지 지도 자동 갱신, 파트너별 보고서. 구매/주문/CRM API 연동, 사용자 장기 프로파일, 고객 행동 화면 녹화는 범위 밖이다.

## 11. 완료 기준

- 끄기 모드에서는 이벤트 감지와 평가 요청이 발생하지 않는다.
- 기본 모드에서는 모델 호출 없이 기존 문구를 표시한다.
- 서비스 구간 노출 시나리오에서는 해당 업체의 실제 주제와 연결된 질문으로 접근하고, 클릭 후 첫 질문과 고객 답변을 이어서 상황을 확인한다. 비교를 제안한 경우에는 실제 대상의 비교를 제공한다.
- 단순 짧은 방문·민감 페이지·현재 상담·직접 채팅 시작에는 제안하지 않는다.
- 클릭 원문에 이메일·전화번호가 있어도 모델 입력이나 DB 메타데이터에 남지 않는다.
- 페이지·주 관심 구간 변경, 탭 숨김, 채팅 열기 중 도착한 오래된 응답을 표시하지 않는다.
- 한 페이지에서 여러 서비스 설명을 스크롤해도 구간별 노출과 재진입을 구분한다. 빠른 스크롤에는 구체적 관심을 단정하지 않는다.
- 첫 질문은 한 번에 하나이며 연락처·예산부터 요구하지 않는다. 클릭만으로 구매 의도를 확인했다고 처리하지 않는다.
- 같은 구간만 잠깐 보거나 구간 자동 분할이 실패하면 상황별 제안을 생략하거나 낮은 수준의 신호로 처리한다.
- 한 방문 최대 2회 평가·1회 표시, 새로고침·SPA·일반 이동에서도 닫기 상태 유지.
- timeout·키 없음·한도 초과는 안전한 기본 문구로 처리하며 이유를 관리자에게 설명한다.
- 서버에서 봇 권한·구독·기능 설정·속도·월 한도를 다시 검증한다.
- 네트워크 재시도·동시 요청은 같은 평가 ID로 중복 비용 예약과 기록을 방지한다.
- 실제 상담이나 신청을 만들지 않고 관리자 테스트를 반복할 수 있다.
- 실제 위젯 모바일/데스크톱에서 구간 감지·노출 시간·제안 표시, 클릭, 닫기와 다음 페이지 이동을 검증한다.

## 12. 파일럿 평가

고정 인사 대비 상황별 제안을 동일한 방문 조건에서 비교한다. 클릭률만으로 성공이라고 결론내리지 않는다.

- 제안 노출 대비 클릭, 클릭 후 실제 질문·상담 신청 연결.
- 닫기 비율, 반복·부적절한 제안 신고.
- 방문당 모델 호출·토큰·평가 비용, p95 응답 지연.
- 제안 종류별 자료 근거 적합성, 구간 식별·주제 연결 적합성, 클릭 후 질문과 응답의 연속성, 불필요한 반복 질문.

아이디얼 테크에서 한 페이지의 여러 구간/긴 구간/빠른 스크롤/구간 재진입/접힘·펼침/모바일/관심 구간 변경/고객의 거절·다른 질문/주제 탐색/문의 관심/모르는 페이지/과거 대화/직접 채팅/닫기/느린 응답 등 20개 이상 고정 시나리오를 준비한다. 예상 제안 여부와 근거를 사람이 검토한 뒤 실제 방문 실험을 시작한다.

## 13. 구현 전 남은 결정

- AI 모델과 키 비용 부담 주체, 플랜별 월 평가 한도.
- 페이지 지도에 사용할 사이트 자료 범위와 갱신 방식.
- 메타데이터 보유·집계 정책과 사이트의 방문자 안내.

현재 구현은 구간 자동 감지·지식 기반 상담 질문·대화 연결·분석 한도·관리자 테스트를 포함한다. 플랫폼별 과금 상품화와 A/B 실험은 후속 결정 사항이다.
