# 실시간 조회 테스트 시나리오 (PRD-db-live-lookup)

대상: 통합 브랜치 `codex/db-knowledge`. [PRD](../PRD-db-live-lookup.md) §6 인수 테스트 L1~L15와 §3 범위 제한 G1~G8을 단계 A·B 검사로 나눈다. 코드 작업 전에 작성했고, 단계가 머지될 때마다 §4 실행 기록을 갱신한다.

표기: **자동** = 단위(`tests/db-live-lookup.test.ts`)·DB(`tests/db-live-lookup.integration.ts`, QA "고객사 DB"에 실제 질의) · **수동** = QA 서버(3013) 브라우저 절차(캡처는 `docs/verification/db-live-lookup/`) · **미검증(환경)** = 실제 OpenAI 키가 있어야 확인 가능.

## 0. 실행 방법

DB 지식 테스트와 같은 격리 QA 환경(`/tmp/chatbot-qa-runtime/app-3013.env`, 로컬 Docker "고객사 DB")을 쓴다. 시드가 `menu` 표에 `stock`(남은 수량)·`size` 컬럼을 추가한다.

```sh
ENV=/tmp/chatbot-qa-runtime/app-3013.env
node --env-file=$ENV --import tsx scripts/seed-db-knowledge-qa.ts
node --import tsx --test tests/*.test.ts
PORTAL_DB_CHECK=1 node --env-file=$ENV --import tsx tests/db-live-lookup.integration.ts
```

QA 서버에는 OpenAI 키가 없으므로 "모델이 어떤 도구를 고르는지"는 도구 호출 결과를 직접 넣는 방식으로 검사한다(채팅 라우트의 도구 실행 함수 단위). 실제 모델이 질문에 맞게 조회를 고르는지는 미검증(환경)으로 남기고 운영 키로 1회 확인한다.
